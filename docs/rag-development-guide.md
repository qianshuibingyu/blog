# RAG 全链路开发指南

本文用于指导 OwnerBlog 后续实现 RAG 知识问答功能。内容重点不是具体代码，而是明确：

- 后续应该按照什么顺序实现；
- 每个阶段要实现哪些功能；
- 每个阶段依赖前一个阶段提供什么结果；
- 每个阶段完成后如何判断可以进入下一阶段；
- 最终如何验证 RAG 全链路已经打通。

## 一、最终要实现的完整链路

```text
文章审核通过
  ↓
创建索引任务
  ↓
判断输入类型
  ↓
PDF / 扫描文档等原始文件 ──→ MinerU 解析为 Markdown / JSON
Markdown 文章 ───────────────→ 直接进入内容校验
  ↓
LangExtract 提取结构化信息和原文位置
  ↓
Markdown 清洗
  ↓
文本切分
  ↓
保存文章片段和来源 metadata
  ↓
生成文章 Embedding
  ↓
写入向量库
  ↓
记录索引结果
  ↓
文章变为 published + indexed

用户提问
  ↓
问题校验
  ↓
生成问题 Embedding
  ↓
检索文章片段
  ↓
过滤非公开和低相关结果
  ↓
组织回答上下文
  ↓
调用回答模型
  ↓
返回答案和来源
```

其中：

- **MinerU** 负责把 PDF、扫描文档或复杂排版文件解析成后续可以处理的 Markdown/JSON；已经是 Markdown 的博客文章可以跳过 MinerU。
- **LangExtract** 负责从解析后的文本中抽取标题、主题、实体、关键事实等结构化信息，并尽量保留原文位置，供 metadata、检索过滤和来源展示使用。
- **索引流程**负责把文章转换成可检索的知识；
- **检索流程**负责从知识库中找到相关内容；
- **生成流程**负责根据检索结果组织答案；
- **发布流程**负责保证只有索引成功的文章才能公开和参与问答。

## 二、当前项目的实现起点

当前项目已经具备：

- `Article` 文章模型；
- Markdown 原文保存；
- 文章审核状态；
- 文章索引状态字段；
- `ArticleChunk` 文章片段模型；
- Chroma、Embedding 和模型相关依赖配置；
- 公开文章必须同时满足 `published + indexed` 的访问条件。

当前还需要逐步实现：

- 文章索引服务；
- MinerU 原始文档解析适配器；
- LangExtract 结构化抽取和原文位置映射；
- Markdown 清洗；
- 文本切分；
- ArticleChunk 实际写入；
- Embedding 调用；
- Chroma 写入、查询和删除；
- 审核通过后的自动索引；
- 索引成功后的正式发布；
- 知识库检索；
- 回答模型调用；
- 问答 API 和前端真实联调。

因此，后续不要一次性直接开发问答页面，而应按照下面的阶段逐步实现。

# 三、推荐实现顺序

## 阶段 0：统一基础约定

### 本阶段目标

先确定所有后续功能共同使用的规则，避免做到后面再修改数据结构和接口。

### 本阶段需要实现或确定的功能

1. 确定哪些文章可以进入知识库；
2. 确定文章什么时候开始索引；
3. 确定索引成功和失败时的文章状态；
4. 确定文章片段包含哪些信息；
5. 确定向量库中每条记录如何关联文章和片段；
6. 确定问答接口的请求和响应结构；
7. 确定答案必须返回哪些来源信息。

### 推荐规则

只有满足以下条件的文章，才允许被公开展示和问答检索：

```text
Article.status = published
Article.index_status = indexed
```

文章状态建议按照以下流程变化：

```text
draft
  → pending_review
  → indexing
  → published
```

索引失败时：

```text
indexing
  → index_failed
```

### 本阶段完成标志

- 文章发布条件已经明确；
- 草稿、待审核和失败文章不会进入知识库检索；
- 后续所有模块都使用同一套文章、片段和来源规则。

---

## 阶段 1：实现文章索引入口

### 本阶段目标

让审核通过后的文章能够正式进入 RAG 索引流程。

### 本阶段需要实现的功能

1. 管理员审核通过文章；
2. 将文章设置为索引中；
3. 创建一次索引处理流程；
4. 记录当前索引步骤；
5. 记录索引开始时间和文章版本；
6. 防止草稿或待审核文章直接触发索引；
7. 支持失败后重新索引。

### 索引入口的职责

索引入口只负责启动流程和更新状态，不负责把所有处理逻辑都写在审核接口中。

启动后依次进入：

```text
  → 校验文章
  → 判断输入来源（Markdown 或原始文件）
  → MinerU 解析原始文件（如需要）
  → LangExtract 抽取结构化信息和来源位置
  → 清洗内容
  → 切分文本
  → 保存片段和 metadata
  → 生成向量
  → 写入向量库
  → 完成索引
```

### 本阶段完成标志

- 审核通过后文章会进入 `indexing`；
- 索引流程能够被调用；
- 索引失败时文章不会被错误设置为 `published`；
- 失败文章可以再次发起索引。

---

## 阶段 2：实现原始文档解析和结构化抽取

### 本阶段目标

为 RAG 增加 MinerU 和 LangExtract 处理层，同时保留当前博客 Markdown 文章的直接入库路径。

### 先明确两个组件的边界

```text
PDF / 扫描文档 / 复杂排版文件
  → MinerU
  → Markdown / JSON
  → LangExtract
  → 结构化字段 + 原文位置
  → 清洗、切分和向量化

已有 Markdown 文章
  → 跳过 MinerU
  → LangExtract（按需要启用）
  → 清洗、切分和向量化
```

- MinerU 是文档解析器，不是 embedding 模型，也不是向量数据库。
- LangExtract 是结构化信息抽取器，不负责向量检索和最终问答。
- 这两个组件都运行在后端入库流程，不能在 Vue 浏览器端调用。
- 如果当前只支持用户填写 Markdown，先实现 Markdown 入口；不要为了使用 MinerU 强行把 Markdown 转成 PDF 再解析。

### MinerU 需要实现的功能

1. 接收 PDF 或后续支持的原始文件；
2. 将文件解析为 Markdown 或 JSON；
3. 保留标题、段落、表格、图片、公式和代码等结构信息；
4. 记录原始文件名、解析版本和解析结果；
5. 解析失败时停止当前索引并记录错误；
6. 不覆盖数据库中作者提交的原始 Markdown。

建议统一产出一个内部文档对象：

```text
{
  source_type: "markdown" | "mineru",
  markdown: "解析后的 Markdown",
  blocks: [...],
  source_name: "原始文件名",
  parser_version: "..."
}
```

Markdown 文章可以直接构造这个对象，不必调用 MinerU。

### LangExtract 需要实现的功能

1. 接收 MinerU 输出或现有 Markdown 文本；
2. 提取标题、章节、主题、实体、关键事实等结构化信息；
3. 保存每条抽取结果在原文中的起止位置或引用文本；
4. 将抽取结果转换成 chunk metadata；
5. 抽取失败时保留基础正文切分能力，并记录警告或错误；
6. 不把模型抽取结果当作作者原文。

metadata 可以先采用以下形式：

```text
{
  article_id: 1,
  title: "文章标题",
  section: "第二章",
  topics: ["Django", "RAG"],
  entities: ["Chroma"],
  source_start: 120,
  source_end: 480,
  parser: "mineru",
  extractor: "langextract"
}
```

第一版不需要一次抽取所有字段。建议先验证“章节标题 + 主题 + 原文引用位置”，确认结果稳定后再增加实体和关键事实。

### 本阶段完成标志

- Markdown 文章可以不依赖 MinerU 进入后续流程；
- PDF 或其他原始文件可以通过 MinerU 产出统一 Markdown/JSON；
- LangExtract 可以输出至少一种结构化字段和原文位置；
- 解析和抽取失败有明确状态，不会误标记为索引成功；
- 生成的 chunk 能够保留文章 ID、章节和来源位置信息。

---

## 阶段 3：实现文章内容校验和 Markdown 清洗

### 本阶段目标

把文章原始 Markdown 转换为安全、稳定、适合后续处理的文本。

### 本阶段需要实现的功能

1. 检查标题和正文是否为空；
2. 检查文章长度是否合理；
3. 统一换行符、编码和基础空白；
4. 保留标题层级；
5. 保留段落、列表、引用和表格内容；
6. 保留代码块和必要的语言信息；
7. 处理危险 HTML、脚本和样式；
8. 删除无意义的格式噪音；
9. 保留文章中的数字、术语和专有名词；
10. 生成清洗后的文本；
11. 记录原文版本或内容指纹。

### 原文和清洗结果的关系

```text
Article.content
  = 作者原始 Markdown，始终保留

cleaned_content
  = 用于后续切分和向量化的清洗文本
```

不能用清洗结果覆盖作者原始文章内容。

### 本阶段输出

```text
文章 ID
原始内容版本
清洗后的纯文本
清洗结果长度
清洗是否成功
```

### 本阶段完成标志

- 一篇有效 Markdown 文章可以得到稳定的清洗文本；
- 空文章会被拒绝；
- 清洗结果不会包含脚本和危险内容；
- 标题、段落、列表、代码等重要内容没有丢失；
- 清洗失败时不会进入文本切分。

---

## 阶段 4：实现文本切分

### 本阶段目标

将清洗后的长文章拆分为多个可独立检索的知识片段。

### 本阶段需要实现的功能

1. 按标题和段落优先切分；
2. 对过长段落继续拆分；
3. 设置每个片段的最大长度；
4. 设置相邻片段的重叠长度；
5. 保留标题或章节信息；
6. 尽量保持代码块和完整语义；
7. 删除空片段；
8. 为每个片段生成连续编号；
9. 保证相同输入得到稳定结果。

### 本阶段输出

```text
[
  {
    chunk_index: 0,
    content: "第一个文章片段"
  },
  {
    chunk_index: 1,
    content: "第二个文章片段"
  }
]
```

### 本阶段完成标志

- 短文章可以生成一个片段；
- 长文章可以生成多个片段；
- 片段之间存在合理重叠；
- 片段编号连续；
- 没有空片段；
- 标题、正文和代码内容没有被无故删除。

---

## 阶段 5：实现文章片段持久化

### 本阶段目标

将切分结果保存到数据库，使每个片段可以追溯到原文章。

### 本阶段需要实现的功能

1. 保存文章与片段的关联；
2. 保存片段顺序；
3. 保存清洗后的片段内容；
4. 为每个片段预留向量记录 ID；
5. 删除文章旧片段并重新生成新片段；
6. 防止重复索引产生重复片段；
7. 保证片段保存失败时不会留下半套数据。

### 重新索引时的处理

```text
读取新文章内容
  → 生成新片段
  → 替换旧片段
  → 生成新向量
  → 更新索引状态
```

同一篇文章重复索引后，数据库中只能保留当前有效的片段集合。

### 本阶段完成标志

- 数据库可以查看某篇文章的全部片段；
- 片段顺序正确；
- 重新索引不会追加重复数据；
- 文章内容更新后旧片段会被替换；
- 每个片段都能追溯到对应文章。

---

## 阶段 6：实现 Embedding 服务

### 本阶段目标

将文章片段和用户问题转换为可以进行相似度比较的向量。

### 本阶段需要实现的功能

1. 将文章片段批量转换为向量；
2. 将用户问题转换为向量；
3. 使用同一个 Embedding 模型处理文章和问题；
4. 支持批量处理；
5. 设置请求超时；
6. 处理模型服务不可用、超时和空响应；
7. 校验向量数量和片段数量一致；
8. 记录 Embedding 失败原因；
9. 模型更换后支持重新索引。

### 本阶段输出

```text
文章片段 → 片段向量
用户问题 → 问题向量
```

### 本阶段完成标志

- 每个有效片段都能获得一个向量；
- 一个问题可以获得一个问题向量；
- Embedding 失败会中断索引或检索；
- 不同模型生成的向量不会混用。

---

## 阶段 7：实现向量库写入和管理

### 本阶段目标

将文章片段向量保存到 Chroma，并支持后续查询、更新和删除。

### 本阶段需要实现的功能

1. 创建或连接向量集合；
2. 保存片段向量；
3. 保存清洗后的片段文本；
4. 保存文章 ID、标题和片段编号；
5. 保存索引版本或内容指纹；
6. 使用稳定的向量记录 ID；
7. 支持重复索引时更新原有记录；
8. 支持文章更新时删除旧向量；
9. 支持文章下架或删除时清理向量；
10. 检查数据库片段和向量库记录是否对应。

### 本阶段完成标志

- 文章片段可以在向量库中查询；
- 每条向量都能定位到文章和片段；
- 重复索引不会增加重复向量；
- 旧文章片段不会继续被检索；
- 删除或下架文章后，其向量不会继续参与问答。

---

## 阶段 8：完成文章索引和发布联动

### 本阶段目标

把前面的处理步骤串成完整的文章索引流程。

### 本阶段需要实现的功能

```text
审核通过
  → 文章进入 indexing
  → 内容校验
  → Markdown 清洗
  → 文本切分
  → 保存文章片段
  → 生成 Embedding
  → 写入向量库
  → 保存向量关联信息
  → index_status=indexed
  → status=published
```

如果失败：

```text
任一步骤失败
  → index_status=failed
  → status=index_failed
  → 保存失败步骤和错误信息
  → 等待管理员重试
```

### 本阶段完成标志

- 审核通过的文章可以自动完成索引；
- 索引成功后才正式发布；
- 索引失败时文章不会公开；
- 管理员可以重新索引失败或过期文章；
- 公开文章 API 能读取索引成功的文章。

---

## 阶段 9：实现公开知识检索

### 本阶段目标

根据用户问题，从向量库中找到相关的公开文章片段。

### 本阶段需要实现的功能

1. 接收用户问题；
2. 校验问题是否为空以及是否超长；
3. 将问题转换为向量；
4. 查询向量库；
5. 按相似度排序；
6. 过滤低相关结果；
7. 限制返回片段数量；
8. 回查文章和片段数据库记录；
9. 再次检查 `published + indexed`；
10. 移除草稿、失败、下架和孤立片段；
11. 返回可用于回答的来源片段。

### 本阶段输出

```text
问题
  → 相关片段列表
  → 文章标题、文章 ID、片段编号和片段内容
```

### 本阶段完成标志

- 问题能够返回相关公开片段；
- 草稿和下架文章不会被检索；
- 低相关问题返回空结果；
- 返回结果数量和上下文长度可控；
- 每个检索结果都能追溯到真实文章。

---

## 阶段 10：实现基于检索结果的回答

### 本阶段目标

让回答模型只依据检索到的文章片段生成答案。

### 本阶段需要实现的功能

1. 将问题和检索片段组织成上下文；
2. 向模型明确说明只能依据提供的资料回答；
3. 要求资料不足时明确说明无法确认；
4. 防止文章片段中的文字改变系统规则；
5. 限制上下文长度；
6. 处理模型超时和异常；
7. 处理模型返回空答案；
8. 不把模型回答写回文章正文；
9. 保留真实检索来源。

### 无相关内容时的规则

```text
没有合格检索结果
  → 不调用回答模型
  → 返回无相关内容
  → sources 为空
```

### 本阶段完成标志

- 回答内容来自检索片段；
- 没有相关内容时不会自由编造；
- 回答结果带有真实来源；
- 模型异常时能够返回明确错误。

---

## 阶段 11：实现知识问答 API

### 本阶段目标

为前端提供统一的问答接口。

### 推荐接口

```text
POST /api/knowledge/chat
```

### 请求内容

```text
question：用户问题
```

### 成功结果应包含

```text
answer：回答内容
sources：来源文章和片段
```

来源至少包含：

- 文章 ID；
- 文章标题；
- 片段编号；
- 用于展示的片段摘要；
- 文章详情链接所需信息。

### 本阶段需要实现的功能

1. 校验请求参数；
2. 调用公开检索流程；
3. 没有结果时返回无结果状态；
4. 有结果时调用回答流程；
5. 返回答案和来源；
6. 处理 Embedding、向量库和回答模型错误；
7. 保持错误响应格式稳定；
8. 防止接口返回草稿或下架内容。

### 本阶段完成标志

- 前端可以通过一个接口完成问答；
- 接口能返回答案和来源；
- 无结果、参数错误和服务错误能够区分；
- 匿名用户和登录用户都只能使用公开文章范围。

---

## 阶段 12：完成前端真实联调

### 本阶段目标

将前端从 mock 问答切换为真实后端问答。

### 本阶段需要实现的功能

1. 关闭前端 mock；

### 本阶段完成标志


# 四、最终验收顺序

建议按照以下顺序进行验收：

## 1. 验收文章索引

- 创建一篇 Markdown 文章；
- 提交审核；
- 管理员审核通过；
- 确认文章进入索引中；
- 确认文章完成清洗和切分；
- 确认数据库保存文章片段；
- 确认向量库保存片段向量；
- 确认文章变为 `published + indexed`。

## 2. 验收公开检索

- 提出一个文章中明确存在答案的问题；
- 确认可以检索到正确片段；
- 提出一个文章没有涉及的问题；
- 确认返回无相关内容；
- 确认草稿、失败和下架文章不会出现在结果中。

## 3. 验收知识问答

- 确认问题能够生成答案；
- 确认答案附带真实来源；
- 确认回答不会超出文章内容随意编造；
- 确认模型异常时能够提示错误；
- 确认前端可以正常显示答案、来源、空结果和错误状态。

## 4. 验收更新和删除

- 修改已索引文章；
- 确认旧片段和旧向量不会继续被检索；
- 重新索引后只保留最新内容；
- 下架或删除文章；
- 确认文章、片段和向量都不再参与问答。

# 五、RAG 全链路完成标准

只有以下流程全部成功，才能认为 RAG 已经完成：

```text
审核通过
  → 内容校验
  → Markdown 清洗
  → 文本切分
  → ArticleChunk 持久化
  → Embedding
  → Chroma 写入
  → 索引状态更新
  → 文章正式发布
  → 问题 Embedding
  → 公开片段检索
  → 上下文组织
  → 回答模型生成
  → 答案和来源返回
  → 前端真实展示
```

最终必须满足：

- [ ] 每个阶段都有明确输入和输出；
- [ ] 文章只有索引成功后才能发布；
- [ ] 用户问题可以检索公开文章片段；
- [ ] 回答只基于检索结果；
- [ ] 答案包含真实来源；
- [ ] 无相关内容时不会编造；
- [ ] 文章更新、下架和删除后不会残留旧知识；
- [ ] 前端可以完成真实问答联调。
